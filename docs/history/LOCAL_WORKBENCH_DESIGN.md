# 历史设计：本地记录与理解工作台（非当前产品架构）

更新日期：2026-10-29。本文是当前产品方向的依据。历史原型已归档在 `legacy/virtual-child` 分支，当前分支仅保留成长镜像。

## 1. 产品定位

为家庭提供一面随孩子成长的数字镜子：保存真实经历，理解情境中的变化，让孩子逐渐参与解释自己的故事。不是复制人格、替孩子发言或预测未来的数字分身，也不是心理诊断工具。

主要使用者是记录真实生活的家庭，以及逐渐具备参与意愿和能力的孩子。不再把“无孩子用户的虚拟养育陪伴”与真实成长记录混在同一产品路径中。

**产品中心是理解孩子，不是写日记。** 记录是素材层；动态成长镜像、情境理解、阶段对照和持续核对才是主流程。Day One仅用于视觉参考，不决定功能和信息架构。此前“本地可用版”只完成素材底座，不能等同于原产品目标已实现。

## 2. 已确认的设计原则

- 先记录经历，再讨论解释；事实、转述、孩子表达、成人假设分别保存和展示。
- 每条解释保留作者、时间和对应事件；允许多个视角并存，不以成人意见覆盖孩子的理解。
- 既记录快乐、好奇、合作和普通日常，也记录困难；不把记录次数当作行为发生率。
- 不输出人格总分、安全感数值、性格定型、诊断或未来预测。
- AI只能检索和整理有出处的材料；不确定就说未知，不能编造原话、补全记忆或把推演写成事实。
- 孩子的解释权、参与意愿和隐私控制随理解能力逐渐增加，而非按固定生日机械切换。
- 数字角色是可选的导航载体，不是心理权威；不以逼真程度作为心理有效性的证明。
- 不采用连击奖励、焦虑打卡、排名或依赖式陪伴来促活。

首期采用清晰的二维 Web 工作空间，不投入开放世界、3D建模或声音克隆。

### 成长理解工作空间（纠偏后）

使用者提供的 Day One 截图只用于留白、灰白蓝和阅读质感。首页不再是日记封面、记录日计数或日历，记录索引只在“经历与依据”出现。

- 主导航为成长镜像、理解工作室、阶段对照；原文检索与导出、档案与数据为辅助入口。
- 成长镜像：六个观察窗口展示本阶段家庭整理的最新理解或有出处的孩子原话；无材料、无理解时保留未知，不自动补全性格。
- 理解工作室：心理学通用知识 → 原始情境与不同声音 → 显式选择依据／反例 → 家庭整理理解、其他解释、待核实问题和支持尝试 → 以后追加修订。不是改名后的关键词查询，也不冒充自动AI分析。
- 阶段对照：前一个等长时期与本阶段同主题材料并排；只帮助比较情境和视角，不输出趋势分数、因果结论或年龄常模。
- 索引按真实发生月份分组，展示日期、标题、观察摘要和补充视角数。搜索覆盖原话与后补视角；主题和日期可展开筛选。
- 日历为周一开始的实际日期网格，支持月切换与单日筛选；与当前日期筛选同步。圆点只代表档案覆盖，不暗示行为频率。
- 经历和记录表单是资料工具，不设日更、连击或能力计分；完整原文检索保留为辅助入口。
- 未提交的记录及各条经历的补充表单在普通面板切换、筛选和来源跳转时保留；成功提交才重置相应表单。关闭页面并不持久化草稿；替换档案、切换空间或重新载入前须提示未保存输入。
- 记录、补充和昵称有独立的放弃按钮，需确认，不影响已保存资料；设置页说明尚有多少处未保存输入。记录列表每页50段、来源跳转定位对应分页；只挂载当前详情及仍有补充草稿的详情。
- 窄屏导航重排为两行，记录列表与内容交替显示；返回箭头打开列表。未加密的本地原型提示保持可见。
- 原有事实／假设区分、孩子参与选择、引用来源、读写错误和删除边界不因样式调整而弱化。档案管理集中放置昵称、空间、备份恢复与清空。

## 4. 记录方法与数据契约

### GrowthEvent：真实事件

- `id`：随机标识；`occurredOn`：家庭填写的事件日期，独立于系统记录时间。
- `createdAt`：实际录入时间（ISO时间）。
- `title`、`context`、`observation`：标题、情境、可观察行为；不自动改写。
- `topic`：情绪与调节、同伴与关系、自主与表达、兴趣与探索、坚持与调整、日常与快乐之一。这是组织信息的框架，不是标准化量表。
- `observer`、`source`：记录者称呼和来源（亲眼观察／他人转述）。不要求真实姓名。
- `childQuote`：可选的、记录者提供的孩子原话，明确尚未由系统核实；空值代表未记录。
- `interpretation`：可选的记录者理解，始终标注“待确认”，不是事实。
- `support`、`question`：可尝试的支持和留待以后询问的问题，不是疗效承诺。
- `perspectives[]`：追加的孩子视角／成人视角／更正，每项保存作者、提交者标注的来源、时间和内容。
- 孩子视角可选 `response: agree | disagree | skip`：分别表示录入者记录的认可、不同理解、暂不回答；不验证身份。认可／不同理解可不附加文字；暂不回答时内容必须为空，不追问原因。已有不含此字段的版本1档案继续兼容。

### 镜像档案

`schemaVersion: 1`、`childName`（可选昵称）、`events[]`、可选 `understandings[]`。使用独立的本地存储键 `neon_buddy_growth_mirror_v1:<spaceId>`。旧档案不含理解字段可直接读取，不自动合成描述；新备份不能交给不识别扩展字段的旧版编辑。

### GrowthUnderstanding：可修正的阶段理解

- 保留主题、起止日期、作者、录入时间、条件化描述 `statement`、另一种解释 `alternative`、待核实问题 `question`、可选支持 `support`。
- `evidenceIds` 至少一项，`counterEvidenceIds` 可为空但提示缺少反例，不暗示反例不存在。两类不能重复；引用必须存在且处于理解的日期范围内，每类最多100项。
- `status` 为探索中／当前工作理解；两者都不是科学定论或孩子认可。
- 修订追加新ID，`supersedes` 只能指向同主题的已有最新版本；旧版本仍可回看，不重写真实事件。
- 最多500份（包括旧版本）；与事件／视角共用唯一ID校验。完整JSON包含理解和修订，沿用5MB整体上限。
- 删除原始依据或反例，级联删除依赖理解及其后续修订；删除理解只影响该版本及后续修订，不影响原始事件。删除前明确告知，已导出副本不能撤回。
- 既有理解引用的经历有更晚补充时提醒重新核对；少视角、缺孩子表达、无反例分别提示，不计算置信度。
- 未提交理解草稿在普通导航和来源跳转时保留；更换主题／日期／修订对象前确认放弃。外部变更后停用旧画像与依据，保留草稿的只读复制入口，不允许过期保存。
- 理解草稿尚未处理时不允许删除已存理解；若经来源页删除了草稿依赖的依据或旧版本，保留输入并明确提示过期，复制／放弃后再重新整理，不自动把旧草稿变成新结论。

### 心理学如何进入功能

将回应式互动、自我决定理论、多报告者视角转成观察问题与可选支持提示，内容可查看研究来源。明确区分通用知识、这个孩子的原始证据、家庭提出的假设；通用理论不能证明个体解释成立。回应式互动的婴幼儿适用背景在页面说明。未采集年龄，不输出发展常模、依恋类型、量表结果或诊断。提问和支持是产品化引导，不声称本产品已通过心理有效性验证。

不采集生日、定位、人脸、声纹、学校、诊断等资料；不接入外部模型。不读取历史原型的存储，因为旧条目可能混有剧情、推断和模拟反馈；删除旧代码不删除用户已有浏览器资料。

### 更正与删除

原始叙述不会因追加视角被覆盖；通过“更正／不同理解”保留修订脉络。这不是不可删除的审计日志：用户可确认删除单条事件（含其全部视角），或清空当前本地空间。首期没有持久化摘要、向量索引或云副本。

档案备份为明文JSON，可恢复到新的本地空间；恢复前校验版本、字段、日期、枚举、标识唯一性和长度，并要求确认替换。回顾可另行导出明文Markdown，不能作为JSON恢复。应用无法删除用户已经下载或自行复制的文件，界面必须说明这一点。

### 损坏恢复与外部变更

读取结果区分可用快照、已读到但不可解析的原始文本、完全无法访问存储。不可解析时保留原始文本及其修订值，不把它当空档案；只允许下载原始文本副本或经明确确认恢复有效备份。存储不可访问时不能假装能够备份或恢复。恢复与普通保存同样比较修订值，文件读取期间发生的并发变化也不得被覆盖。

正常写入和JSON导出共用紧凑序列化，UTF-8不超过5MB，与导入上限一致；超限不写入，旧资料保留。历史超大原始资料可下载文本副本。原始副本可能损坏或不兼容，不得提示“备份校验成功”。

监听当前空间的 `storage` 事件，并在页面获得焦点、恢复或可见时重查原始修订。发现变化或核对失败后停用旧列表、概览事实与回顾引用，阻止保存和删除，不自动重读覆盖表单。当前记录、补充和昵称输入保留供复制或主动放弃；设置页提供未保存补充的入口。重新载入须确认丢弃未保存输入，清除过期问答后展示最新资料。该机制仍不是跨窗口事务锁，建议同空间只用一个编辑窗口。

本地启动使用固定来源 `http://127.0.0.1:52947/`，端口占用时明确失败、不回退到另一端口；仅监听本机。来源或浏览器变化不会共享localStorage，迁移必须先导出再恢复。`npm start` 构建并运行本地静态预览，不是正式线上部署。

## 5. 第一阶段实现边界

- 成长镜像为唯一入口；历史原型仅保留在独立分支，当前代码无模拟养成或云快照逻辑。
- 本地空间仅用于同浏览器数据分组，不是登录、身份验证或访问权限系统。
- 多视角由当前使用者手工录入并注明来源，不声称验证了提交者身份或孩子同意。
- localStorage没有应用级加密；同设备、同浏览器来源的访问者可能读到内容。仅供本地原型使用，不承诺生产级保密。
- 读写失败、数据损坏、版本不支持必须显式显示；失败时不覆盖原数据、不清空输入，也不显示保存成功。
- 不后台自动采集、不上传、不生成模拟事件；记录和视角均需主动提交。

## 5.1 P1本地回顾与问答（已实现部分）

- `ReviewScope` 使用实际事件日期及可选主题，默认近30天；回忆长廊筛选与回顾范围各自独立，界面明确显示。
- `Evidence` 包含事件ID、可选视角ID、原文、作者、来源、字段类型、事件日期及实际录入时间。观察、原话、假设、支持设想和后补视角始终分开。
- 阶段回顾只说明档案覆盖情况并列出摘录，不推断成长趋势、人格、因果或支持效果。后补视角附属于原事件，不声称在事件发生时就已获知。
- 问答明确标注“本地记录检索版”：问题用于说明目的，另填关键词和记录类型；按标题、情境、主题或相应原文字面匹配。不具备语义理解、同义检索或生成能力。
- 无依据时给出不足提示；诊断、人格、因果和未来预测类问题给出能力边界提示。边界词识别只是辅助，真正的限制是系统只返回原文，不进行推理或生成。
- 每条摘录可回到原始事件；跳转会重置长廊筛选，但不会卸载或清空尚未提交的表单。
- 不持久化问答历史、素材选择、派生摘要或索引；问答结果绑定提交时的档案、回顾范围与素材选择。任一变化立即隐藏旧结果，取消未完成任务，需重新提交；恢复替换、空间切换和清空重置问答。
- Markdown回顾保存范围、事件／视角ID、来源和原文；导出副本无法随应用删除自动撤回。
- 这些是P1的本地基础，并不代表已完成自然语言AI对话、正式儿童认证或共享授权。

## 5.2 可替换检索接口与素材边界（已实现）

当前只接入 `local-literal-v1` 浏览器字面检索适配器，无网络调用或模型依赖。先固定可验证的检索契约，不在未确认部署与数据方案时选择模型、服务商或新增后端。模型生成与语义模型仍属未实施项，不能把接口准备称为AI对话已完成。

| 层 | 契约及约束 |
|---|---|
| 素材选择 | 初始为空；只能明确选择当前范围内的事件。拒绝重复、已删除或越界ID；新记录不自动加入，改变范围清除选择。 |
| 服务输入 | `RetrievalInput` 仅含 `keyword` 与 `documents`。每项含引用、标题、情境、主题、对应类型的原文和标签。不传整个档案、昵称、作者或未选类型的正文；本版问题只在本地做边界提示，不传给检索服务。 |
| 服务接口 | `RetrievalService.retrieve(input, signal): Promise<unknown>`，提供适配器ID、显示名和匹配方式。UI固定使用本地适配器，无用户可配置端点、密钥或外部服务入口。 |
| 服务输出 | 严格为 `{ references: [{ eventId, field, perspectiveId? }] }`。只允许当前已选素材、所选类型中的引用；拒绝额外的生成文字／作者字段、未知引用、错误视角ID与重复项。 |
| 页面结果 | 从本次提交的档案快照恢复原文、作者、来源、事件及视角录入时间。服务不能替换引用正文，也不能把记录者理解转换成孩子原话。 |
| 生命周期 | 加载、取消、失败和无依据分别提示；失败不自动切换其他服务。取消立即结束等待，即使适配器忽略信号，迟到结果也不能显示。档案／范围／选择变化立即隐藏旧结果，并清除组件保存的旧回答与提交快照，取消任务。 |

素材选择仅约束问答，不限制上方阶段回顾和Markdown导出；界面必须明确区分。选择和检索状态只存在当前页面内存，刷新或重新载入后不保留。普通面板切换和来源跳转不主动清除输入、素材与仍有效的结果。

输出校验只能保证引用确实来自所选原文，不能证明检索相关性、心理有效性或获得了儿童同意。未来接入语义模型仍需相关性与多视角覆盖评估；生成式回答需要独立的逐句引用、假设、反例与不确定性契约，不能在当前引用接口里夹带生成文字。设备本机模型也需要部署资源确认；云端服务另须明确授权、数据最小化、加密及留存方案，不因已选素材而自动获得发送许可。

## 6. 后续AI与场景的约束

AI层必须建立“真实记录／可撤回的派生内容／虚构推演”三类隔离。回答需包含事件ID和引用片段，假设保留模型版本、生成时间、依据、反例及待核实状态。删除原记录时必须同步处理依赖摘要、索引、缓存与云端副本。

真实回顾只能展示已有记录；虚构练习不得生成心理分数；假设推演不能当作孩子本人意见，不能自动回写档案。照片表情、单次游戏、心率均不等于特定心理状态。

共享与云端上线前需完成身份认证、细粒度授权、撤回机制、数据留存与备份删除策略、加密、供应商数据使用核查和适用地区的合规评估。正式量表需另行核查适龄范围、中文效度、授权及专业解释要求。

## 7. 成功标准

不是“用户多停留几分钟”或“数字人像不像”，而是：

1. 用户能以自己的话完成一次记录，并区分观察与理解。
2. 回顾时能找到原始依据，看见不同视角，而非获得单一人格定论。
3. 孩子能够表达不同意见或选择不参与。
4. 家庭认为记录负担可接受，并带来了更具体、少标签化的交流。
5. 导出、恢复、删除、失败提示可用；未发现将虚构当作真实记录的路径。

## 8. 研究与产品依据

以下材料是设计参考，不构成对本产品心理有效性的验证。查阅日期：2026-10-29。

- [Storypark：儿童档案与故事](https://help.storypark.com/en/articles/56237-families-children-s-profiles-and-stories)：具体经历、多媒体档案及家庭参与的产品形式。
- [Day One：功能](https://dayoneapp.com/features/)：低负担记录、检索、回看与导出。
- [Mightier：研究与游戏机制](https://www.mightier.com/science/)：具体调节技能练习的参考；官网包含不同研究设计，效果不能直接移植到新产品。
- [De Los Reyes 等，2015，多报告者评估综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC4486608/)：341项研究显示不同报告者对应程度有限；差异可能涉及情境、视角及测量因素。临床评估证据不等于家庭日记已经被验证。
- [哈佛儿童发展中心：回应式互动](https://developingchild.harvard.edu/key-concept/serve-and-return/)：产品应促进而非替代真实亲子交流。
- [自我决定理论：理论概览](https://selfdeterminationtheory.org/theory/)：自主、胜任与联结作为理解支持环境的观察视角，不用作个体需求测评分数。
- [UNICEF：AI与儿童指南第三版](https://www.unicef.org/innocenti/reports/policy-guidance-ai-children)：安全、隐私、透明、参与和儿童最佳利益。
- [Generative Agents，2023](https://arxiv.org/abs/2304.03442)：可信行为模拟的交互参考，不是儿童数字孪生验证。
- [基于个人自述的LLM模拟研究，arXiv:2411.10109](https://arxiv.org/abs/2411.10109)：特定问卷与实验任务的预测评估，不支持复制儿童内心或预测长期成长的承诺。
