# Neon Buddy 项目总计划（Implementation Plan）

更新时间：2026-04-17

## 1. 项目愿景

以真实育儿体验为基础，构建一个可持续成长的虚拟孩子与虚拟世界。
用户通过记录真实生活事件，获得孩子的情感回应、成长反馈和长期记忆沉淀，从而形成“被理解、被陪伴、可回顾”的养育体验。

## 2. 产品定位

- 目标用户：
  - 有孩子的家长（记录与陪伴）
  - 暂无孩子但有情感陪伴需求的人群
- 首版平台：Web
- 首版交互：2D 剧情 + 养成
- 真实映射阶段策略：先手动记录真实事件，再考虑自动化映射

## 3. 核心设计原则

- 真实优先：事件来自真实生活，而非纯虚构任务
- 连续记忆：互动可沉淀、可追溯、可回顾
- 心理学支撑：关键反馈有儿童发展心理学解释
- 伦理安全：不做情绪操控式留存，不做重度依赖机制
- 小步快跑：优先验证情感价值，再扩展复杂系统

## 4. 目标指标（MVP）

- 行为指标：
  - D1 留存
  - D7 留存
  - 周记录频次
  - 单次会话时长
- 体验指标：
  - “像真实养育体验的一部分”访谈正向比例 >= 60%
- 安全指标：
  - 审核样本中无心理操控、无不当育儿建议、无诱导依赖

## 5. 分阶段路线图

### 阶段A：价值定义与边界锁定（第1-2周）

1. 明确双人群共性任务：每日 5-10 分钟获得被回应的养育体验
2. 定义北极星指标与 MVP 成功门槛
3. 锁定伦理与安全红线
4. 输出“真实感来源框架”：真实输入、可信规律、记忆回响、挫折修复

### 阶段B：核心玩法与世界建模（第2-4周）

1. 最小场景集：家、户外、公园、睡前
2. 孩子成长状态机：年龄阶段、需求、情绪、亲密度、好奇心、安全感
3. 真实事件映射流水线：记录 -> 标签 -> 剧情片段 -> 状态改写
4. 育儿专家知识卡：关键互动后提供简短行为解释

### 阶段C：MVP 产品化（第4-10周）

1. 核心闭环：登录 -> 记录事件 -> 场景互动 -> 孩子反馈 -> 当日总结
2. 内容系统：剧情模板库、事件模板库、里程碑模板、鼓励反馈模板
3. 数据记忆系统：时间线、事件回看、成长相册、每周总结
4. 非强迫留存机制：以分享成长瞬间驱动回访，不使用焦虑文案

### 阶段D：验证与迭代（第10-14周）

1. 20-50 人内测，覆盖两类目标用户
2. 复盘“真实感、被理解感、陪伴价值”与核心指标
3. 若 D7 不达标，优先优化日循环与反馈质量
4. 伦理复审并形成上线前安全清单
5. 决策下一阶段：自动映射 / 语音互动 / 场景扩展

## 6. 功能清单（按优先级）

### P0（必须）

1. 真实事件输入（类型、强度、文本）
2. 事件影响成长状态（安全感、亲密度、好奇心、情绪）
3. 孩子反馈生成（回应 + 心理学提示）
4. 成长时间线
5. 本地持久化

### P1（推荐）

1. 每周成长报告
2. 内容规则配置化（JSON）
3. 伦理文案过滤层
4. 育儿专家卡片库（带来源）

### P2（扩展）

1. 自动化真实映射（相册/时间线）
2. 语音互动
3. 多角色陪伴体系（家长/祖辈）
4. 账号体系与云端同步

## 7. 风险与对策

- 范围失控：坚持 P0/P1/P2 分层，任何新增需求必须归档到对应层级
- 内容生产过重：先模板化，再个性化
- AI 成本与延迟：先规则驱动，后接入模型
- 伦理风险：上线前必须通过文本安全抽检
- 留存不足：优先优化反馈质量，不堆叠功能复杂度

## 8. 验证方案

1. 可用性：新用户 3 分钟内完成首次完整闭环
2. 情感价值：访谈问题围绕“被理解感、真实感、回访动机”
3. 业务可持续：单用户周维护成本可控

## 9. 当前落地状态（已完成）

当前项目已实现无依赖 Web 原型，支持以下能力：

1. 真实事件录入
2. 状态映射与成长阶段推进
3. 反馈文案生成（孩子回应 + 心理学提示）
4. 成长时间线
5. localStorage 持久化

对应文件：

- index.html
- styles.css
- app.js
- README.md

## 10. 产品收敛原则（2026-07）

当前优先服务 2–8 岁儿童家长，核心闭环是“记录一次真实互动 → 理解孩子可能的感受 → 获得一个下一步动作”。报告、勋章、奖励和家校协同作为辅助能力，不应遮挡首次记录和最近反馈。

上线前必须保留以下边界：

- 明确产品不是诊断、治疗或专业育儿咨询的替代品。
- 默认本地保存，提供数据导出与删除入口；mock-local 不包装成真实云端。
- 反馈使用观察性、概率性语言，避免羞辱、恐吓和诱导依赖。
- 用首次闭环完成率、反馈有帮助比例和安全抽检结果验证价值，而不是只追求功能数量。
